# 🤖 AI 活用設計（公開インフラ維持管理マップ）

> 状態: 設計確定（実装は Phase 3） / 関連: 総合評価 2026-08-12

## 1. 目的と非目的

- ✅ 目的: 調査・検索・取込・品質確認の時間削減、判断の参考情報提供
- 🚫 非目的: 健全性・安全性・工事可否の自動判定、専門家判断の代替、チャット機能の目的化

## 2. ユースケースと方式

| ユースケース | 方式 | 人間承認 | 根拠・引用 | 優先度 |
| --- | --- | --- | --- | --- |
| 自然言語検索 | RAG + 構造化検索ハイブリッド（資産メタ・原典テキスト） | 不要（閲覧のみ） | 常に原典 URL・信頼度表示 | P1 |
| 公開資料からの属性抽出 | LLM 構造化抽出（JSON Schema 強制） | 要（取込前レビュー） | 抽出元ページ・行範囲 | P1 |
| 取込異常検知 | 統計/ルールベース異常検知（AI は補助） | 要（公開判断） | 過去件数・属性分布 | P2 |
| 維持管理計画の参考要約 | RAG（法令・点検要領・資産詳細） | 要（専門家） | 条文・要領の引用 | P2 |
| 品質 issue の平易な説明 | 要約生成 | 不要（表示のみ） | 生成ログ・issue リンク | P3 |

## 3. モデル構成

- 基本: 公開データ・日本語に強い小型モデル（コスト優先）＋必要時のみ大型モデルへのルーティング
- 埋め込み: 資産属性・原典テキストをベクトル化（費用対効果を実測してから本採用）
- 検索: 既存のキーワード AND・都道府県/市区町村フィルタを第一段とし、RAG は補助
- 構造化: JSON Schema による出力検証＋取り込み前の human-in-the-loop

## 4. 安全性・ガバナンス

| 項目 | 設計 |
| --- | --- |
| 権限制御 | AI は公開データのみ。社内情報・PII はデータ方針どおり接続しない |
| プロンプトインジェクション | 外部データをシステム命令と分離・出力をスキーマ検証・原典リンク強制 |
| 個人・機密保護 | 入力・出力に PII 検出（公開データ限定のためリスク低） |
| 監査 | モデル・プロンプト・入出力ハッシュ・トークン量を監査テーブルへ記録 |
| 誤判定責任 | 常に免責表示＋「最終判断は専門技術者・管理主体」。AI の判定を公開データの事実と混ぜない |
| 予算上限 | 月次トークン上限・アラート・キュー制御・モデル段階ルーティング |
| 停止手段 | 機能フラグ・API キー無効化・設定変更・コスト上限で即時停止 |

## 5. AI を使わない領域

- 正規化（NFC・日付・単位・座標系）: ルール（実装済み）
- 重複検出・品質ルール Q001〜Q008: 決定的ルール（実装済み）
- ライセンス判定・出力可否: 契約ベースのルール（実装済み）
- レート制限・認証認可: ルール（実装済み）

## 6. 実装手順（Phase 3 冒頭）

1. 監査テーブルとコストメトリクスの migration
2. 自然言語検索の PoC（サンプルデータ・50 クエリ評価）
3. 構造化抽出 PoC（アダプター候補 1 件）＋人間レビュー UI
4. 異常検知 PoC（既存取込履歴から実測）
5. 評価結果（精度・コスト・時間削減）を Issue 化し継続判断
